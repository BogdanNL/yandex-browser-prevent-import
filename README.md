# Запрет импорта в Яндекс Браузер

Я собрал здесь скрипты и конфигурации для Windows, Linux и macOS, чтобы отключить автоматический импорт при первом запуске Яндекс Браузера и импорт отдельных категорий данных из других браузеров по инициативе пользователя.

**Применяйте настройки до установки и первого запуска браузера.** Установщик может запустить браузер сразу после установки. Уже импортированные данные эти настройки не удаляют.

Я сверил набор с официальной документацией **Яндекс Браузера для организаций** 25 сентября 2026 года. Поддержку политик в обычной версии и конкретной сборке рекомендую проверять через `browser://policy`: я не проверял все выпуски браузера. Синхронизацию с аккаунтом Яндекса и копирование профиля средствами ОС эти настройки не контролируют.

## Политики

Я задал все девять политик как обязательные со значением `false` (в Windows — строка `0`). В таблице привёл ссылки на официальное описание каждой политики.

| Политика | Что отключается |
| --- | --- |
| [ImportOnFirstRun](https://browser.yandex.ru/support/browser-corporate/ru/policy/import-on-first-run) | Автоматический импорт при первом запуске |
| [ImportBookmarks](https://browser.yandex.ru/support/browser-corporate/ru/policy/import-bookmarks) | Импорт закладок |
| [ImportHistory](https://browser.yandex.ru/support/browser-corporate/ru/policy/import-history) | Импорт истории посещений |
| [ImportLastSession](https://browser.yandex.ru/support/browser-corporate/ru/policy/import-last-session) | Импорт открытых вкладок |
| [ImportSearchEngine](https://browser.yandex.ru/support/browser-corporate/ru/policy/import-search-engine) | Импорт настроек поисковых систем |
| [ImportExtensions](https://browser.yandex.ru/support/browser-corporate/ru/policy/import-extensions) | Импорт расширений |
| [ImportOther](https://browser.yandex.ru/support/browser-corporate/ru/policy/import-other) | Импорт системных настроек браузера |
| [ImportSavedPasswords](https://browser.yandex.ru/support/browser-corporate/ru/policy/import-saved-passwords) | Импорт сохранённых паролей |
| [ImportCookies](https://browser.yandex.ru/support/browser-corporate/ru/policy/import-cookies) | Импорт cookie |

Одного `ImportOnFirstRun` недостаточно для запрета последующего ручного импорта, поэтому я добавил остальные восемь политик.

## Windows

1. Откройте `cmd.exe` от имени администратора и перейдите в папку репозитория.
2. Выполните:

   ```bat
   YandexBrowser_Disable_All_Imports_Windows.cmd
   ```

Скрипт также можно запускать от имени SYSTEM. Он задаёт девять значений в `HKEY_LOCAL_MACHINE\SOFTWARE\Policies\YandexBrowser`, то есть на уровне компьютера. При запуске из 32-битного агента на 64-битной Windows используется `Sysnative\reg.exe`.

Тип `REG_SZ` и значение `0` соответствуют [инструкции Яндекса по настройке через реестр](https://browser.yandex.ru/support/browser-corporate/ru/deployment/windows/setting-policy). ADMX/ADML для этого способа не требуются.

Повторный запуск перезаписывает эти девять значений. Остальные параметры сохраняются. Код завершения: `0` — команды выполнены, `5` — нет доступа к разделу HKLM, `1` — ошибка записи или контрольного чтения. При ошибке часть значений могла уже примениться; исправьте причину и запустите скрипт повторно.

Если в `browser://policy` появилась строка без имени с ошибкой «Неизвестное правило», проверьте реестр:

```bat
reg query "HKLM\SOFTWARE\Policies\YandexBrowser"
```

При наличии пустого значения `(Default) REG_SZ` удалите только его из командной строки администратора:

```bat
reg delete "HKLM\SOFTWARE\Policies\YandexBrowser" /ve /f
```

Параметр `/ve` выбирает безымянное значение — девять именованных политик сохранятся ([документация Microsoft](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/reg-delete)). Затем перезагрузите политики в `browser://policy`. Я убрал из скрипта отдельную команду создания раздела без имени параметра; теперь он сразу записывает `ImportOnFirstRun`. Уже существующее значение `(Default)` скрипт автоматически не удаляет. Эта правка касается ошибки безымянной политики; её влияние на предложение импорта не подтверждено.

## Linux

Сохраните скрипт и JSON в одной папке и выполните:

```sh
sudo ./install_yandex_disable_all_imports.sh
```

Требуются `/bin/sh` и стандартные утилиты Linux: `id`, `dirname`, `install`, `mktemp`, `cat`, `chown`, `chmod`, `mv`, `rm`. Браузер пока может быть не установлен.

Скрипт читает JSON рядом с собой независимо от текущей рабочей папки и устанавливает его в:

```text
/etc/opt/yandex/browser/policies/managed/disable_all_imports.json
```

Каталог получает владельца `root:root` и права `0755`, файл — `root:root` и `0644`. Замена файла атомарная: сначала готовится временный файл, затем переименовывается. Повторный запуск заменяет только `disable_all_imports.json`.

При ручном развёртывании можно поместить предоставленный JSON в этот каталог, обеспечив чтение для пользователей и запись только для администратора. Это каталог обязательных политик; `recommended` для запрета не подходит. Яндекс разрешает произвольные имена JSON и объединяет настройки из нескольких файлов — см. [настройку политик в Linux](https://browser.yandex.ru/support/browser-corporate/ru/deployment/linux/setting-policy).

## macOS

До первого запуска браузера нужным пользователем выберите один из двух вариантов:

- **Один комбинированный профиль:** можно попробовать установить [YandexBrowser_Disable_All_Browser_Imports.mobileconfig](YandexBrowser_Disable_All_Browser_Imports.mobileconfig) со всеми девятью политиками. Я проверил его установку: после установки одного файла все девять политик отображаются в `browser://policy`.
- **Отдельные профили:** установите **все девять** файлов из [macos/](macos/). Этот вариант следует описанному в документации Яндекса подходу «одна политика на файл».

В [инструкции Яндекса для macOS](https://browser.yandex.ru/support/browser-corporate/ru/deployment/mac-os), в разделе локальной настройки, сказано: «В одном шаблоне можно заполнить информацию только об одной политике». У меня комбинированный профиль работает. Из документации я не смог однозначно понять, относится ли эта фраза к примеру шаблона или к техническому ограничению, поэтому оставил оба варианта. После установки комбинированного профиля проверьте все девять значений и их состояние в `browser://policy`; если они не применились, удалите его и используйте отдельные профили.

Установка выбранного варианта:

1. Откройте файл `.mobileconfig` двойным щелчком в Finder.
2. В Системных настройках откройте **Основные → Управление устройством**, выберите загруженный профиль и завершите установку. В более ранних версиях macOS раздел может называться **Конфиденциальность и безопасность → Профили**.
3. При использовании отдельных профилей повторите для остальных восьми файлов. Для комбинированного профиля достаточно одной установки. Простого открытия файла недостаточно.

Порядок установки и удаления описан в [руководстве Apple](https://support.apple.com/ru-ru/guide/mac-help/mh35561/mac).

В каждом профиле указаны домен `ru.yandex.desktop.yandex-browser`, логическое значение `<false/>` и `PayloadScope=User`. Настройки относятся к пользователю, установившему профиль; для других пользователей потребуется отдельное развёртывание. Профили не подписаны. Для централизованной установки используйте MDM с учётом пользовательской области действия.

Рекомендую использовать один выбранный вариант, чтобы не дублировать политики в нескольких установленных профилях. При переходе удалите профили предыдущего варианта. Для комбинированного файла я сохранил исходные идентификаторы и UUID, а отдельным профилям задал уникальные. При обновлении существующего профиля сохраняйте его идентификаторы.

## Другие источники политик

До развёртывания проверьте существующие GPO, MDM, настройки Консоли управления и локальные конфигурации: они могут задавать другие значения тех же политик. Устраните конфликты в их источниках.

Отдельно проверьте:

- [ImportFrom](https://browser.yandex.ru/support/browser-corporate/ru/policy/import-from) выбирает исходный браузер, а не запрещает импорт. Документация указывает приоритет политик отдельных категорий над ним; в этом наборе он не задаётся.
- [YandexImportBookmarksPath](https://browser.yandex.ru/support/browser-corporate/ru/policy/yandex-import-bookmarks-path) включает отдельный однократный импорт закладок из указанной папки в расширенной версии. Он должен быть не настроен или отключён. Не следует предполагать, что `ImportBookmarks=false` отменит этот механизм: такой приоритет на странице политики не указан.

Скрипты не удаляют эти дополнительные настройки автоматически. При необходимости отключите их в том источнике, который их задаёт. Общий перечень механизмов приведён в [документации по переносу данных](https://browser.yandex.ru/support/browser-corporate/ru/deployment/transfer).

## Проверка результата

1. После применения настроек запустите браузер и откройте `browser://policy`.
2. Нажмите **Повторно загрузить политики** (название кнопки зависит от версии).
3. Найдите все девять политик из таблицы. У каждой должны быть значение `false`, обязательный уровень применения и состояние **ОК**, без ошибок и конфликтов.
4. В настройках импорта убедитесь, что импорт соответствующих категорий недоступен.

Для проверки первого запуска используйте отдельную тестовую учётную запись ОС с данными другого браузера: примените политики, затем установите и запустите Яндекс Браузер. Проверка на уже использовавшемся профиле не подтверждает поведение первого запуска.

При подготовке репозитория я проверил синтаксис shell, корректность JSON/plist и совпадение наборов политик на трёх платформах. Linux-установщик проверил изолированно, во временном каталоге с имитацией прав root. На macOS я проверил установку комбинированного профиля: все девять политик появились в `browser://policy`. Версии macOS и браузера для этой проверки я не зафиксировал. Поведение импорта при первом запуске и ручного импорта отдельно не проверял; испытания в браузере на Windows и Linux не проводил.

## Отмена изменений

Если политики были настроены ранее, перед применением сохраните их значения, чтобы затем восстановить.

- **Windows:** удалите только девять значений из таблицы в указанном разделе реестра либо восстановите прежние значения. Не удаляйте весь раздел `YandexBrowser`, если в нём есть другие политики.
- **Linux:** удалите `/etc/opt/yandex/browser/policies/managed/disable_all_imports.json` либо восстановите его предыдущую версию.
- **macOS:** удалите комбинированный профиль `Yandex Browser — Disable All Browser Imports` или установленные отдельные профили `Yandex Browser - Disable Import…` через Системные настройки или MDM.

Затем перезапустите браузер и проверьте `browser://policy`. Политики из других источников могут продолжать действовать. Отмена запретов может вновь разрешить импорт.
